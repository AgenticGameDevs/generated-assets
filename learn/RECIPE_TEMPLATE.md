# Recipe and walkthrough template

Copy the sections below into a new Markdown file under `learn/`. Replace the prompts with your actual process and remove inapplicable sections. A useful post can be short: one repeatable result with evidence is enough. See [the learning hub](README.md) for publishing steps.

## Title and outcome

What will the reader make, and where is it useful? State whether this is a tested recipe, an illustrative brief or an account of an experiment. Link any submitted assets by stable ID or gallery URL.

## Author, tools and inputs

Credit the contributor and any collaborators. Name tools and versions, relevant settings, source files or references, and their sharing rights. Distinguish original work from third-party inputs. Say which prerequisites require a paid service without promising a current price.

## Brief, prompt or parameters

Include the actual instructions, source code or parameter values needed to reproduce the important decisions. If the tool is stochastic, record available seed/settings and describe what variation to expect. A prompt alone does not guarantee the illustrated result.

## Work and export

Explain the generation or authoring steps, cleanup, naming, file format, scale/orientation, texture or audio settings, and why they were chosen. Prefer commands or small examples the reader can inspect. Mark steps that depend on software not included in this repository.

## Evidence and known limits

Show or link the exported file and its actual preview. Describe what you checked: tiling, alpha, rig motion, import behavior, audio tail, size or checksum. Give tested tool versions where relevant. State what remains unverified and any failed approach that helps the reader avoid the same problem.

## Contribution and next variation

Identify the descriptor, license, attribution and collection for any accompanying asset. Suggest one useful variation or improvement. Invite reproduction reports through a PR or discussion rather than presenting untested outputs as approved assets.

## Review before submitting

Keep the article focused, credit sources and check every local link. Do not include credentials, signed URLs or private reference material. Guide-only PRs can mark binary/asset checks as not applicable; any accompanying media must follow the normal contribution rules. Code and documentation here use MIT; media keeps its per-file license.
